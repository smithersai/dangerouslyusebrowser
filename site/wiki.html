Start here

Dub (DangerouslyUseBrowser) is a real Chromium 157.0.8082.0 fork that exposes browser internals directly to coding agents through native C++20 N-API bindings and an incur MCP server. It is not Playwright, not a stock-CDP wrapper, and not Electron.

Why a real Chromium fork

Stock automation protocols sit outside the browser engine's privileged seams. Dub patches Chromium directly at the C++ browser, renderer, V8, Blink, and NetworkService boundaries so agents can:

  • Rewrite, block, redirect, and decode-patch network traffic across tabs, dedicated/shared/service workers, CacheStorage, and HTTP cache (DEMO-01).
  • Freeze, advance by 31 days, and frame-step a single tab's V8 + Blink clock while leaving sibling tabs in the same renderer on real wall time (DEMO-02).
  • Attach to a persistent profile, dispatch native Chromium actor input (isTrusted: true), and call live WebMCP page tools (DEMO-03).
  • Run persistent QuickJS TypeScript code-mode cells, typed Jev evaluators, reactive push-stream triggers, and hot-reloadable TypeScript plugins (Milestone 4).

Evidence rule

Dub separates bridge-fixture tests from compiled-fork browser proofs. Transport fixtures validate N-API framing, deadlines, MCP schemas, auth, and QuickJS runtimes, never Chromium behavior. Compiled-fork browser behavior is verified by DUB_BROWSER=/path/to/chrome npm run test:browser and archived under docs/evidence/2026-11-23/README.md.

C++20 N-API bridge and IPC protocol

Dub keeps Chromium out-of-process so the browser's multiprocess sandbox, UI loop, and V8 isolates remain isolated from Node.js. Communication crosses a small C++20 N-API v8 addon (native/addon.cc, native/dub.cc, native/dub.h) over a private local AF_UNIX socket.

Protocol v1 wire format

+---------------------------+----------------------------------------+
| uint32 big-endian length  | UTF-8 JSON payload (1 byte to 16 MiB)  |
+---------------------------+----------------------------------------+
  • Request envelope: {"protocol":1,"id":"<uuid>","method":"<name>","params":{...},"timeoutMs":30000}
  • Response envelope: echoes id and carries either result or {"error":{"code":"...","message":"..."}}.
  • Whole-call deadlines: dub_call enforces an absolute monotonic deadline. A stalled browser or slow one-byte trickle cannot reset the timer.
  • No silent retries: Timeout or disconnect never implies rollback and never retries side-effecting commands automatically.

Push event stream (subscribe)

Milestone 4 added NativeBridge.subscribe() backed by persistent non-blocking AF_UNIX streaming in native/addon.cc and native/dub.cc. Chromium pushes live network callbacks, console entries, dialogs, navigations, downloads, and exposed page calls into Node without polling, powering src/triggers.ts and src/plugins.ts.

Compilation and safety invariants

scripts/build-native.mjs compiles native/addon.cc and native/dub.cc with:

-std=c++20 -O2 -Wall -Wextra -Werror -fPIC -shared -DNAPI_VERSION=8
  • Zero abort(), exit(), or std::terminate() calls are allowed in native/ (enforced continuously by Uphill's cpp-no-abort gate).
  • Prebuilt binaries ship under prebuilds/darwin-arm64/dub.node and prebuilds/linux-x64/dub.node, and scripts/install.mjs compiles on demand when a matching prebuild is absent.
  • tests/native.test.mjs and tests/fuzz.test.mjs verify fragmented UTF-8 reads, parallel calls, whole-call deadlines, slow trickles, 120 malformed/truncated/oversized frames, and clean subscription teardown.

NetworkService rewrite and per-tab engine clock

Dub's first two flagship proofs attack the two hardest limits of stock browser automation: universal network control and engine-coherent time travel.

DEMO-01: NetworkService-level interception

Navigation-only hooks miss fetch, dedicated workers, shared workers, service workers, and cache hits. Dub installs DubNetworkInterceptor directly inside Chromium's NetworkService (chromium/overlay/services/network/dub/dub_network_interceptor.cc) synchronized over Mojo from the browser process (chromium/overlay/chrome/browser/dub/dub_network.cc).

Verified capabilities (tests/browser/milestone-2-network.test.mjs):

  • Live rule add, list, remove, and precedence evaluation without restarting tabs.
  • Mock responses (status, headers, body/JSON), request blocking, redirects, header mutation, and decoded-body search/replace patching (no double-patching across gzip/chunked streams).
  • Coverage across top-level navigation, fetch, dedicated/shared/service workers, CacheStorage, and HTTP disk cache.
  • Bounded net log --follow stream with explicit gap reporting when entries rotate.

DEMO-02: Per-tab isolated V8 and Blink clock

Process-wide virtual time perturbs Chromium internals and corrupts sibling tabs sharing a renderer process. Dub patches V8 and Blink (0004-milestone-3-per-tab-clock.patch) with page-scoped clock domains while keeping browser IPC deadlines and network housekeeping on real monotonic time.

Verified capabilities (tests/browser/milestone-3-clock.test.mjs):

  • Freeze at an arbitrary ISO epoch (clock.freeze) and synchronize Date.now(), new Date(), performance.now(), setTimeout, setInterval, requestAnimationFrame, and CSS animations.
  • Advance 31 days (clock.advance --by 31d) with bounded interval fire caps so infinite page timers cannot hang the browser.
  • Step exact animation frames (clock.stepFrames) and verify committed compositor pixel diffs via screenshot.
  • Same-renderer isolation: two same-origin tabs verified to share one renderer PID stay independent (tab A freezes/jumps while tab B stays on wall clock).
  • DedicatedWorker inheritance and monotonic resume (clock.resume).

Persistent profiles, native actor tools, and WebMCP

DEMO-03 gives agents direct access to real authenticated browser sessions through persistent Chromium profiles, native trusted input, and page-registered WebMCP tools.

Persistent profile ownership (src/launch.ts)

  • By default, dub serve creates and owns an isolated persistent profile directory so cookies, IndexedDB, and session storage survive browser restarts without touching the user's daily browser.
  • Explicit --profile or profile attach can select an existing compatible Chromium profile. Dub respects Chromium's ordinary profile lock and never extracts, copies, or inspects credential databases during development.
  • Closing the last window does not terminate a serving session; the selected profile remains pinned until explicit shutdown (SIGINT/SIGTERM).

Native Chromium actor tools

Instead of synthesizing untrusted DOM clicks, Dub invokes Chromium's native actor delegates (actor.click, actor.type, actor.select, actor.scroll, actor.upload_file, and navigation actions) from the browser process:

  • Dispatched events arrive in the page with isTrusted: true.
  • Text and selector targeting detects stale targets and returns Chromium's native failure codes.
  • File upload reads only the explicitly named local fixture path.

Live WebMCP page tools (dub_frame.mojom)

When a web application registers tools through WebMCP (navigator.modelContext), Dub's renderer observer (chromium/overlay/chrome/renderer/dub/dub_render_frame_observer.cc) tracks tools dynamically across frames and navigations:

  • tools list returns current tool names, JSON input schemas, and frame IDs.
  • tools call invokes the registered page handler and preserves structured return values, rejections, and cancellations.
  • Cross-document navigation invalidates stale registrations so pending invocations never wedge.

QuickJS code mode, Jev, triggers, and TypeScript plugins

Milestone 4 turns Dub into a programmable browser runtime built directly on Smithers primitives (@smthrs/harness, @smthrs/model, and effect). All five runtime subsystems are composed inside DubRuntime (src/runtime.ts).

Smithers QuickJS code mode (src/smithers-runtime.ts)

SmithersCodeRuntime executes TypeScript and JavaScript cells inside persistent, isolated QuickJS REPL realms (@smthrs/harness/Sandbox):

  • Cells call Dub browser operations through typed ctx.call(...) flows (tabs.list, page.evaluate, net.mock, clock.advance, jev.ask, agent.turn, and more) across primitive JSON boundaries.
  • Every cell is bounded by a wall-clock timeoutMs and a maxCalls budget, preventing runaway scripts from stalling the host.
  • Realms retain lexical bindings across frames (realmId) and tear down cleanly on runtime.close().

Typed Jev evaluators (src/jev.ts)

JevClient wraps @smthrs/model/Evaluator so every enumerable browser decision (boolean, choice, or numeric score) runs with typed failure semantics at the seam instead of silent LLM fallback:

  • Supports Vercel AI Gateway in production and deterministic scripted evaluators in tests (Evaluator.layerScripted).
  • Each question instruction is prefixed with its ID to match Smithers StandardFlows conventions.

Reactive triggers and BYO agent bridge (src/triggers.ts, src/agent-bridge.ts)

TriggerEngine subscribes to Chromium's live push stream (net.request, net.response, page.dialog, page.navigate, page.console, page.error, download, ws.message, page.exposed) and executes three reactive modes:

  • code: evaluates a TypeScript cell in QuickJS with event injected.
  • jev: queries JevClient and routes deterministically to a decision, a QuickJS cell, or agent escalation.
  • agent: hands off a structured turn to any BYO agent adapter (CLI such as claude -p, OpenAI, Anthropic, or webhook HTTP endpoint) with Dub's /mcp endpoint attached.

Hot-reloadable TypeScript plugins (src/plugins.ts)

PluginManager loads .ts or .js plugins (definePlugin), transpiles TypeScript via Sucrase, supports --watch hot-reload, registers custom MCP tools, synthetic WebMCP page tools, command middleware, and network callbacks, and tears down every resource atomically on unload or reload.

Cloud MCP server and one-time sandbox auth

Dub dogfoods Smithers Cloud's Bring-Your-Own-Agent (BYOA) MCP architecture in both directions: agents developing Dub connect to Smithers Cloud MCP (https://smithers.sh/api/mcp), and agents driving a browser connect to Dub's authenticated HTTP MCP server (dub serve /mcp) using short-lived, single-use sandbox tokens.

One-time sandbox authentication (src/auth.ts, src/http.ts)

Maintainer / Controller                      Sandbox / BYO Agent
        |                                             |
        |-- POST /auth/one-time-tokens -------------> | (receives dub_ott_... ONCE)
        |                                             |
        |                                POST /auth/exchange {"token":"dub_ott_..."}
        |                                             |---> atomic single-use mark
        |                                             |<--- dub_ses_... (scoped TTL)
        |                                             |
        |                                POST /mcp (Authorization: Bearer dub_ses_...)
        |                                             |---> verified X-Dub-Trust header

Security invariants verified by tests/auth.test.mjs and 200 randomized fuzz trials in tests/fuzz.test.mjs:

  • Loopback default: dub serve binds 127.0.0.1 by default and refuses non-loopback hosts without authentication.
  • Host and Origin pinning: Every HTTP request is checked against the allowed Host allowlist and same-origin policy, blocking DNS rebinding and cross-site requests.
  • SHA-256 hashed storage + timing-safe comparison: Raw dub_ott_... and dub_ses_... secrets are never stored in memory or logs. Only SHA-256 digests are retained and compared via crypto.timingSafeEqual.
  • Atomic single-use redemption: redeemOneTimeToken() marks the token used before emitting the session token. Any replay fails with HTTP 409 (OTT_ALREADY_USED).
  • Untrusted scope attenuation: contributor and viewer principals always carry trust: "untrusted" and are stripped of cache:write, auth:mint, mcp:admin, plugin:manage, and profile:attach.
  • Sanitized audit ring buffer: The last 128 auth events (mint, redeem, replay_rejected, expired_rejected, revoke) are queryable by trusted maintainers on GET /auth/audit with zero secret bytes logged.

Printing one-time tokens for sandboxes and agents

Start Dub with an immediate single-use bootstrap token:

dub serve --port 7777 --print-one-time-token --sandbox-id ci-42

Or mint additional one-time tokens from a running authenticated server or Smithers gateway:

DUB_TOKEN=... node scripts/mint-sandbox-auth.mjs --principal agent:reviewer --role agent --ttlSeconds 120
SMITHERS_TOKEN=... node scripts/mint-sandbox-auth.mjs --target smithers --ttlSeconds 120

Smithers Cloud factory, object store, and trust model

Dub is built publicly as a Smithers Cloud coding factory at smithers.sh/smithersai/dangerouslyusebrowser, mirroring cleanly to github.com/smithersai/dangerouslyusebrowser.

Shared Smithers Cloud object store (.smithers/WORKSPACE.ts)

Every build and test target declared in PACKAGE.ts and .smithers/PACKAGE.ts hashes its exact source closure and declared host binaries (node, npm, bun, c++, sh). Results cache locally in .smithers/cache and sync through the shared Smithers Cloud object store at https://build.smithers.sh using separated credentials:

  • SMITHERS_CACHE_READ_TOKEN: Read-only cache lookup (safe to expose to untrusted runs).
  • SMITHERS_CACHE_WRITE_TOKEN: Cache publication (restricted strictly to trusted maintainer and main-branch controlled sandboxes).

Trusted vs untrusted execution

We actively welcome and encourage non-maintainers to run tests, Uphill audits, and flows on their changes, because most contributors act in good faith. Security holds by construction rather than by blocking contributors:

Capability Trusted (Maintainer / Controlled Sandbox) Untrusted (Non-Maintainer / Fork PR)
Run unit, fuzz, MCP, and Uphill checks Allowed Allowed and encouraged
Read from build.smithers.sh cache Allowed Allowed (read-only)
Write to build.smithers.sh object store Allowed Blocked (no write token)
Modify protectedPaths (.github, .smithers, chromium/patches, native) Allowed with review Flagged and gated for maintainer
Skip quality gates or merge to main Human maintainer only Blocked
Trigger npm release and docs publish Automatic on merge to main Blocked

Lighthouse-style backpressure (.agents/uphill/)

Instead of opaque CI logs, Dub runs Uphill across five scored categories (bridge-safety, typescript-quality, mcp-security, testing-and-fuzz, docs-and-footprint), rendering a Google Lighthouse-style visual audit report (site/audit.html and .uphill/report.html) with 0-100 circular gauges, missed targets, baseline diffs, and opportunities ranked by score impact.

Personalized Factory UI (.smithers/home.json)

The Smithers Cloud homepage adapts automatically to who opens the repository:

  • Maintainer (roninjin10): Opens on the Today cockpit (branch.new hotkey b, live issues, live stack of changesets, live runs, and maintainer flow controls).
  • Contributor: Opens on the Contribute workbench (setup commands, untrusted-to-trusted workflow cards, links to Issues/PRs/Audit/Wiki, and codebase Q&A).
  • Viewer (everyone): Opens on the open-source front door (Hero with install command, quickstart code, verified stats, capability cards, releases, and live audit links).

Automatic release and docs publishing

Merging from Smithers Cloud to GitHub main automatically runs .github/workflows/release.yml, which:

  • Checks whether package.json version moved ahead of npm or whether docs, wiki, site, or audit files changed.
  • Runs full incremental CI (smthrs ci //...) and Lighthouse backpressure (uphill --compact).
  • Rehearses and publishes dangerouslyusebrowser to npm + creates a verified GitHub Release when the version advances.
  • Rebuilds and deploys dangerouslyusebrowser.smithers.sh (landing page, personalized factory UI, live Lighthouse audit report, public wiki, Mythical History, and llms.txt).
